# @loopbackhq/inbox

The [Loopback](https://github.com/bimsonz/loopback) inbox as React components: every ask your agents
raise, in a list, and the one open beside it, answered in place, kept live as agents ask and reply.
It is the inbox Loopback deploys, made to render inside an app of your own, with your sign-in and
your routes around it.

```sh
pnpm add @loopbackhq/inbox @loopbackhq/sdk @cloudflare/kumo @effect/atom-react effect react react-dom
```

## Rendering it

Hand it a client from [`@loopbackhq/sdk`](https://www.npmjs.com/package/@loopbackhq/sdk), and tell it
how your app moves between asks:

```tsx
import { RegistryProvider } from "@effect/atom-react";
import { Inbox, InboxProvider } from "@loopbackhq/inbox";
import { make } from "@loopbackhq/sdk";
import { useMemo } from "react";
import { useNavigate, useParams } from "react-router";

function Asks({ workspace }: { readonly workspace: string }) {
	const { askId } = useParams();
	const navigate = useNavigate();
	// A client per workspace: hand over another, and the inbox follows that one instead.
	const client = useMemo(
		() => make({ baseUrl: location.origin, token: () => tokenFor(workspace) }),
		[workspace],
	);
	return (
		<InboxProvider client={client}>
			<Inbox
				selectedId={askId ?? null}
				onSelect={(id) => navigate(id === null ? `/w/${workspace}` : `/w/${workspace}/asks/${id}`)}
				hrefFor={(id) => `/w/${workspace}/asks/${id}`}
			/>
		</InboxProvider>
	);
}

// Once, around the app: the inbox keeps its state in Effect atoms.
<RegistryProvider>{/* your app */}</RegistryProvider>;
```

`tokenFor` stands for however your app gets a fresh token; the SDK calls it for every request, so a
short-lived JWT is never sent stale.

`Inbox` fills the element it is drawn in, which needs a height. Its shortcuts (digits to pick a
choice, ⌘↵ or Ctrl↵ to send) work from anywhere on the page except your own controls. Where other
people's agents ask in the same space, it offers a switch between everyone's asks and the person's
own agents'.

## Styling

The components are styled with [Kumo](https://www.npmjs.com/package/@cloudflare/kumo) and Tailwind 4
utility classes, generated by your app's Tailwind build. In your stylesheet:

```css
@source "../node_modules/@cloudflare/kumo/dist/**/*.{js,jsx,ts,tsx}";
@import "@cloudflare/kumo/styles/tailwind";
@import "tailwindcss";
@import "@loopbackhq/inbox/styles.css";
```

Kumo themes by `data-mode="light"` or `"dark"` on the root element, which your app sets.

## Around it

- `useInbox()` is the inbox state, for a header that shows whether it is live.
- `useAttention(inbox, notify, open)` keeps the tab title counting what awaits the person, and raises
  a notification for a new ask while the tab is in the background; `useNotifications()` asks the
  browser's permission and remembers the choice.
- `useMe()` and `whoIs(actor, me)` name people as the inbox does: "You", or their name.
